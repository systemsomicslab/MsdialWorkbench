# Shipped rule-set fixtures

Owned by MsdialWorkbench (the C# engine is the oracle); the Python port copies this folder from a pinned commit.
Generated by `ShippedRuleFixtureTests` (CommonStandardTests) from the embedded rule set; every input is synthetic.
`../manifest.json` pins each file's sha256 and case count and, under `rule_set`, the version and rule-set
sha256 of the shipped set they were generated from. The files carry `rule_set_sha256: null` so that the manifest
is the one pin.

- `rules/<rule_id>.json`: 106 files, 1595 cases
- `../masses.json`: 1773 rows
- engine semantics: `msfinder-diagnostic-rules/1`

Both are `{format, format_version, engine_semantics, rule_set_version, rule_set_sha256, kind, cases}` written with
indent 1, `ensure_ascii`, LF and a trailing newline.

## rules/<rule_id>.json

Each case runs on the shipped set restricted to that rule: every `tables/*.json`, `ruleset.json`,
`rules/<rule_id>.json` and the `scaffolds/<list_id>.json` the rule names, loaded unpinned as an inline set
(`ruleset-history.tsv` is not hashed and is left out). A case holds `name`, `description`, `options` (only the
non-default ones: every case has `filter: all`, and `wrong_mode` also `verbose: true` so that its outcome with no
hypothesis is listed), `input` (as in `../engine/semantics.json`), `expect`, `result` (the canonical result
text) and `result_sha256`.

The cases are built constructively by `DiagnosticFixtureBuilder`, independently of the engine: it enumerates
the rule's hypotheses with NCDK's BODR major-isotope masses (electron 0.000549), picks a hypothesis h* of the
rule's own adducts whose positive spectrum makes it the chosen hypothesis, places one peak at the oracle m/z of
every member of every support term of h* (outside the precursor region) plus the precursor peak, and derives:
`positive`; `drop_<term>` for each required term (on h*, or, when h* has no peak of the term, on the first
other hypothesis of the rule's adducts that places one and fires, named in the description; a peak that a
complementary partner shares goes for both terms, and the description names the other); `drop_any<n>` for
each `any` node (pre-order) with the peaks of every support term under it removed; `k_of<n>_at_k` and
`k_of<n>_at_k_minus_1` for each `k_of` node (pre-order); `veto_<term>` for each veto (with a member that
leaves h* chosen and not fired when one exists); `ordering_reversed_<term>`; `tolerance_{in,out}_{high,low}`
(the first required support peak at the product tolerance -/+ 1e-5 Da) and, when that target is below m/z
500, `tolerance_ppm_{in,out}_{high,low}` on the highest support target at or above m/z 500 (the 10 ppm
branch); `precursor_{in,out}_{high,low}` (the precursor at its tolerance -/+ 1e-5 Da); `wrong_mode`; `tie`
(two hypotheses that share a precursor, with the union of their peaks); `decoy_plus_5`. Rules with
`measure: false` are built alike. `expect` is the builder's naive
evaluation (fired, chosen hypothesis, matched `term_id:member_key@peak_index`, ties, `n_hypotheses`,
`precondition_failure`), checked against `result` by the test; `result` is the parity target.

Peaks are integer micro-Da and integer intensities written as decimal text, and sit at least 5e-6 Da from every
tolerance boundary, the precursor region and the loss constraint in the builder's model and at least 2e-6 Da in
the engine's (the test audits both).

## ../masses.json

C# output. A `formula` row per formula of the shipped set (term formulas, plus and minus, unit plus and minus,
composition cores, scaffold formulas and ion formulas, unit residues, adduct add and remove) with its integer
`pda`, `neutral_mass`, `cation_mz` (- e) and `anion_mz` (+ e) as exact decimals of pDa, and the files that
hold it. A `precursor` row per sampled hypothesis: for every rule and tried adduct, the first and the last
composition in enumeration order. The test checks every value against NCDK within 1e-5 Da; the catalog checks
them against RDKit.

## Regenerate

Set `MSDIAL_DIAGNOSTIC_FIXTURES_WRITE=<dir>` and run the CommonStandardTests filter `DiagnosticRules`; every
fixture of this folder's parent is written under `<dir>` and the regeneration tests end Inconclusive. Copy the
files here unchanged. A change to the shipped set (a new version and history row) needs only this run.
