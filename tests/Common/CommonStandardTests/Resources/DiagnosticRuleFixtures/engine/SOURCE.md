# Engine parity fixtures

Owned by MsdialWorkbench (the C# engine is the oracle); the Python port copies this folder from a pinned commit.
Generated by `DiagnosticRuleFixtureParityTests` from the hand-derived cases in
`tests/Common/CommonStandardTests/StructureFinder/DiagnosticRules/SemanticsFixtureCases.cs` and from the
`loader_errors` vectors of `../cjson-vectors.json`. Every input is synthetic.

- `semantics.json` (61 cases): sha256 `c14a6a65c00d44e09577b112e55b7dbd95ef4243b5446a2d85853ac74ad1051d`
- `loader-errors.json` (68 cases): sha256 `b48a33454b6436d56c2f76828a6ff55eb1d5e148eb2c547133ad2bf3ac869314`
- engine semantics: `msfinder-diagnostic-rules/1`

Both files are `{format, format_version, engine_semantics, rule_set_version, rule_set_sha256, kind, cases}` written
with indent 1, `ensure_ascii`, LF and a trailing newline. `rule_set_version` and `rule_set_sha256` are null: each
case carries its own rule set. `../manifest.json` pins each file's sha256 and case count.

## semantics.json

Each case holds:

- `files`: every rule-set file as a JSON object. The bytes loaded are its storage form (sorted keys, indent 1,
  `ensure_ascii`, LF and a trailing newline), loaded unpinned as an inline set. There is no `ruleset-history.tsv`,
  so a pinned load reports only `ruleset_unpinned`. A scaffold list no rule uses is left out.
- `options`: only the non-default ones, with decimal text for doubles.
- `input`: `peaks` as `[m/z, intensity]` decimal text with at most 6 decimals, written from integers;
  `precursor_mz` as text, or null for NaN; `ion_mode` `pos`, `neg` or null; `instrument_type`; `adduct_evidence`
  null or `{adduct, tier}`.
- `expect`: the hand-written expectation; `result`: the canonical result text; `result_sha256`.

Decimal text converts to a double by one correctly rounded division
(Python `float(text)`). Peaks sit at least 2e-6 Da from every tolerance boundary and at least 1e-6 (relative)
from every floor. The deliberate equalities are ratio comparisons of identical doubles: `ordering_equal` (0.4
against 0.4) and `veto_stronger_than_equal` (0.2 against 0.5 * 0.4, where halving is exact).

## loader-errors.json

One case per loader error code: `files` maps each rule-set path to its base64 bytes, `check_pin` is true (the
version pin is checked against `ruleset-history.tsv`), `errors` is the full ordered list `[code, file, pointer]`
and `expect` is the defect's `{code, file, pointer}`. Each list equals the CPython expectation of the same vector.

## Regenerate

Set `MSDIAL_DIAGNOSTIC_FIXTURES_WRITE=<dir>` and run the CommonStandardTests filter `DiagnosticRuleFixtureParityTests`;
the files are written under `<dir>` (this layout) and the test ends Inconclusive. Copy them here unchanged.
